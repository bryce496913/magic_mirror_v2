# Pass 7E reliability and security review

Scope: Passes 7A–7D tool-enabled voice, local wake handoff, state socket, dashboard, weather, search, and existing Pi-hole provider. Automated checks use fake devices and provider responses; Raspberry Pi acceptance is pending.

| Finding | Severity | Resolution |
| --- | --- | --- |
| The search daily-budget `flock` could block a worker thread indefinitely after an asyncio task was cancelled. | Medium | Use a nonblocking exclusive lock and fail closed with `budget_unavailable` if another owner holds it. The search is not sent without a budget reservation. |
| A future provider that ignores asyncio cancellation could leave a tool task alive while voice accepted another question. | Medium | Keep ownership of the task; if it outlives the bounded cleanup grace, close the voice session instead of rearming listening. Late results still cannot send outputs. Bundled HTTP providers honor cancellation. |
| A searched page could influence the Realtime continuation to request another tool in the same user turn. | Medium | Force `tool_choice=none` after any `search_web` call and reject a further tool request locally until a new speech turn starts. Search text remains untrusted data. |
| Voice transcript assembly retained earlier turns for the full session. | Low | Clear transcript assembly on a new speech turn, cap it at eight parts and 2,048 characters per part. The dashboard continues to show only its bounded current exchange. |
| Realtime provider error codes were reflected verbatim into safe-to-display errors. | Low | Accept only short symbolic error codes; replace malformed or free-form codes with `unrecognized_error` so provider text cannot echo private values into the CLI. |
| Tool and session resource/cost diagnostics were insufficient for hardware acceptance. | Low | Add in-memory counts for tool outcomes, total/max latency, budget-reserved search requests and reported tokens, plus session count/duration. Wake CLI prints these with existing CPU/RSS/TCP metrics; no query, transcript, key, or provider body is logged. An optional operator-set per-request price provides a rough search estimate. |

Existing controls confirmed by code review and mocked tests: read-only allowlisted tool names; closed JSON schemas and duplicate-key rejection; bounded argument/output sizes; per-tool deadline and concurrency cap; per-session call ceiling; finite Realtime connect, idle, response and session deadlines; bounded retry counts; fixed HTTPS provider endpoints and disabled redirects; provider response size caps; no model-controlled URL fetch, shell command, file write or GPIO operation; mode-0600 private budget, owner lock and assistant socket; loopback-restricted assistant snapshot endpoint; no idle OpenAI connection; exclusive audio and GPIO ownership. Search requests use normal certificate verification. Pi-hole's custom CA applies only to Pi-hole HTTPS requests, and this pass does not alter its configuration or services.

Residual risks for project-lead and physical review: citations do not independently verify third-party claims or neutralize every prompt-injection attempt; the model may still speak an inaccurate answer. A cancelled search can consume a paid request, and the budget counter intentionally reserves before sending. `asyncio.to_thread` cannot forcibly terminate a thread already in a local filesystem operation, although the budget lock itself no longer waits. Metrics count budget reservations and reported tokens; cancellation between reservation and send can overestimate billable calls, while failed requests may lack token usage. The optional dollar figure excludes Realtime audio and other token charges. Prices and provider/model availability can change. Idle resource use, audio handoff, acoustic feedback, LED behavior, and Pi-hole regression require the Raspberry Pi checklist.
