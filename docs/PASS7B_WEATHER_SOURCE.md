# Pass 7B weather source decision

The dashboard already uses Open-Meteo's forecast API for current temperature, condition, high/low, and tomorrow's short forecast. Its dashboard cache is on an independent background schedule and contains neither hourly rain probability nor a full weekend forecast. The voice tools reuse its configured coordinates, temperature unit, and weather-code descriptions, but make their own query after explicit activation. Voice requests never call `DashboardData.refresh_one()` or reset that worker's timer.

Open-Meteo remains the primary source. Its [forecast API](https://open-meteo.com/en/docs) supports current model conditions, hourly precipitation probability and temperature, and daily high/low through the next eight days in a single request. Its [geocoding API](https://open-meteo.com/en/docs/geocoding-api) resolves named places worldwide, including the US and New Zealand. Both free endpoints require no API key. Current values are **model estimates**, not on-site instrument observations. Location queries are data parameters to a fixed HTTPS endpoint; no model-supplied URL is accepted. Coordinates are retained at source precision. The returned IANA timezone and Unix timestamps determine calendar periods and daylight-saving offsets.

The [free API terms](https://open-meteo.com/en/terms), checked 2026-11-02, permit non-commercial use with fewer than 10,000 calls/day, 5,000/hour, and 600/minute, subject to service restrictions. The free tier has no uptime guarantee. [Pricing and licensing](https://open-meteo.com/en/pricing) state that commercial use requires a paid customer API licence/key; this implementation does **not** assume that the no-key endpoint covers commercial use. Weather data requires CC BY 4.0 attribution to Open-Meteo and underlying sources. Open-Meteo geocoding credits GeoNames. Keep those credits in project material, and attribute Open-Meteo when reporting weather to a user. A commercial deployment needs an explicit licensed endpoint integration before use; no customer key is configured in this pass.

The voice query has a 5-second wall-clock limit per HTTP attempt, at most one retry on transient network/server errors, a 256 KiB response cap, and no redirects. A 429 response stops immediately and yields a rate-limit result. Each active conversation caches up to 16 locations: fresh for `MIRROR_VOICE_WEATHER_CACHE_SECONDS` (default 600), then potentially stale for up to 1800 additional seconds if refreshing fails. Stale results carry `freshness: stale`; older data is unavailable. Explicit city matches with comparable populations remain ambiguous and return candidate labels for clarification. No GPS, hidden place default, persistent transcript, weather key, or idle network request is introduced.

Limits: Open-Meteo can omit individual forecast values and its local forecast accuracy varies by model, geography, and lead time. The short-window rain result uses the maximum available hourly precipitation probability in the requested local period; it is a probability forecast, not proof of rain. The night window is local 18:00–06:00. The weekend is the upcoming Saturday/Sunday, or the current Sunday if queried on Sunday. Sunrise, alerts, precipitation amounts, minute-by-minute nowcasts, and historical observations are outside this pass.
